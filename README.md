## 0.2.37 — NSFW에서 일상으로 돌아오는 답변의 수집 공백

- 이전에는 NSFW 담당으로 생성한 답변에서 일상으로 복귀하면 SFW 상태표 요청이 빠져, 자동보정이 꺼진 경우 첫 복귀 화면에 Info_panel의 장소·시간·날씨만 나올 수 있었습니다.
- 두 확장이 켜진 상태에서는 NSFW 담당 요청에 조건부 SFW 복귀 보고 형식만 추가합니다. 그 답변이 성적 장면을 마치고 일상으로 돌아온 경우에만 현재 인물·소지품·중요 물건을 포함한 상태표를 요청합니다. SFW 진행·금지·속도 지시는 넣지 않으며, 이 보고를 위해 장면을 끝내라는 지시도 하지 않습니다.
- NSFW 담당이 유지되면 기존처럼 SFW에 저장하지 않습니다. 실제 담당이 해제되고 같은 답변의 상태표가 있으면 즉시 수집합니다. 과거 상태를 현재 값으로 복사하거나 보조 AI 호출을 추가하지 않습니다. 모델이 보고 형식을 따르지 않으면 기존 누락 처리와 자동보정 설정을 따릅니다.
- 진단에 조건부 복귀 보고 요청 여부, 수신·저장 물건 수, 서버 응답의 NSFW 온도, 온도/본문 감지로 활성화됐는지를 추가했습니다. 인물·물건 이름과 대화 원문은 로그에 넣지 않습니다.
- 검증: SFW 테스트 60개 통과(NSFW 0.13.19 동시 로드 포함). 조건부 주입, SFW 비활성 시 주입 없음, 실제 해제 후 인물·물건 수집, NSFW 담당 유지 시 수집 차단을 확인했습니다. 모델의 실제 출력 준수 및 특정 장면의 NSFW 판단 정확도는 별개입니다.

## 0.2.35 — 서버 응답부터 수집 후 변경까지 진단

- 진단을 켜면 수집 지시가 포함된 요청의 응답 복사본에서 상태 태그·JSON 파싱 여부·인물 수·출력 한도 종료를 확인합니다. 일반 JSON 응답과 SSE 스트리밍을 지원하며, 읽기 실패·지원하지 않는 형식·불완전 스트림은 태그 누락으로 단정하지 않습니다.
- `server_response_observed`는 fetch 경계에서 읽은 응답입니다. 앞서 설치된 다른 fetch 래퍼가 내용을 바꾸는 경우 제공자 원본이라고 보장할 수 없습니다. 요청 번호로 재작성의 여러 응답을 구분합니다.
- `response_message_link`는 태그를 제외한 본문이 정확히 일치할 때만 요청 번호와 메시지를 연결합니다. 후보가 중복되거나 번역 등으로 본문이 달라졌다면 미확인으로 남깁니다. 서버 응답에 태그가 있었는데 같은 본문의 수신 메시지에는 없었다면 두 단계 사이의 삭제를 구분할 수 있습니다.
- `body_checkpoint`/`body_changed`는 수신 이벤트, 수집 직전/직후의 변화, 변경된 길이, 공백·마크업만 다른지 기록합니다. 자체 태그 제거와 이후 본문 변경을 구분하며 변경한 확장을 근거 없이 지목하지 않습니다.
- 로그는 최근 400건만 보관합니다. 비교용 본문은 제한된 메모리에서만 잠시 사용하고 다운로드·채팅 저장에는 포함하지 않습니다. 응답당 1 MiB/45초, 동시 4건으로 제한하며 로그 비우기·진단 끄기 시 비교 자료와 진행 중 읽기를 정리합니다.
- 원래 fetch Promise와 응답, 요청 내용, 자동보정 설정은 유지합니다. 별도 AI 호출은 없습니다. 이번 변경은 원인을 구분하는 진단 보강이며 태그 누락이나 알 수 없는 본문 변화를 자동으로 해결했다고 보장하지 않습니다.

검증: NSFW 0.13.19와 함께 SFW 테스트 55개 통과. 원응답 소비 보존, JSON/SSE, 추론 텍스트 제외, 누락/읽기 실패 구분, 재작성 후보 연결, 본문 변경, 크기 제한, 진행 중 기록 비우기를 포함합니다.

## 0.2.34 — 저장 후 본문 불일치 구분

- 정상 수집한 상태가 이후 본문 비교에서 탈락해 사라져 보이는 경로를 수정했습니다. CRLF/LF, 줄 끝 공백, 뒤에 붙는 `번역문` 앞의 여백, NSFW 상태 코드 블록 정리로는 새 수집 기록을 무효화하지 않습니다. 일반 본문 내용과 선택 스와이프는 계속 검증합니다.
- 실제 내용이 바뀌거나 원인을 확인할 수 없는 불일치는 **저장 후 본문 변경 · 이전 수집값 표시 (현재 상태 미확인)**로 표시합니다. 해당 답변에 저장된 인물 정보를 확인할 수 있지만, 표시만으로 그 값을 현재 장면 프롬프트에 채택하지는 않습니다. 새 태그 수집 또는 상태 다시 분석으로 갱신할 수 있습니다.
- 진단에 저장 여부·저장 인물 수·태그를 제외한 본문 길이·기록과의 일치 여부를 추가했습니다. `collection_settled`는 자체 재렌더/저장 호출 직후, `cache_invalidated`는 저장 후 본문 불일치이며, 메시지 렌더·편집·스와이프 이벤트도 구분합니다. 원문이나 해시값은 진단 파일에 포함하지 않습니다.
- 기존 기록은 삭제하지 않습니다. 구버전 기록은 기존 비교 방식도 지원하지만, 이미 불일치한 기록을 근거 없이 최신 상태로 승격하지 않습니다. 자동 보정 설정은 유지합니다.
- 기존 로그로 확인된 것은 정상 저장 뒤의 일치 검사 실패입니다. 어떤 후처리가 본문을 바꿨는지는 확정되지 않았으므로 이 버전의 추가 진단으로 확인해야 합니다.

검증: NSFW 0.13.19와 함께 SFW 테스트 45개 통과. 공백/태그 후처리, 번역문 추가, 실제 본문 변경, 스와이프 분리, 기존 기록 호환을 포함합니다. 실제 사용자 환경의 후처리는 추가 재현이 필요합니다.

## 0.2.33 — 기본 수집 진단 기록

- 설정 → 수집 진단 기록에서 켜고 새 답변을 생성한 뒤 JSON을 복사·다운로드할 수 있습니다. 기본은 꺼져 있으며 추가 AI 호출은 없습니다.
- `injection_registered`는 확장 프롬프트 등록, `request_observed`는 같은 서버의 채팅/텍스트 생성 fetch 경계에서 수집 지시를 관찰한 결과입니다. 등록만으로 실제 전송 성공이라고 판정하지 않습니다. 네트워크 기록이 없다면 전송 여부는 미확인입니다.
- `response_observed`는 SFW가 자체 태그를 지우기 전에 본 답변의 구조입니다. 태그 없음·미완성·잘못된 JSON·빈 상태·정상 파싱, 캐시 유효성, 인물 수, 누락 항목을 구분합니다. 다른 확장이 앞서 태그를 삭제했는지나 모델 원출력까지 확정하는 기록은 아닙니다.
- `collection_result`는 저장/기존 기록 사용 결과, `collection_skipped`는 비활성·재생성 대기·NSFW 인계 사유입니다. 자동 보정 꺼짐과 보정 예약·시작·저장·실패도 기록합니다.
- 요청·답변 본문, API 키, 프로필 ID, 인물 이름, 원문 오류는 저장하지 않습니다. 익명 채팅 번호와 메시지/스와이프 번호로 구분하며 최근 150건만 메모리에 보관합니다. 새로고침 전에 내려받으세요.
- fetch 요청·응답·설정은 변경하지 않고 응답 본문을 읽지 않습니다. 꺼지면 관찰을 중지하며 다른 확장의 fetch 래퍼를 덮어쓰지 않습니다. 이번 버전은 진단 기능 추가이며 실제 미수집 원인은 재현 기록으로 확인해야 합니다.

- `scene_state`와 `sfw_scene`를 답변 표시 전에 숨겨. 스트리밍 중 미완성 태그, 코드 블록과 HTML 이스케이프 형태도 처리해. 화면에서 제거하려고 먼저 원문을 지우지 않아서 완료된 답변의 기록 수집은 유지해.

SillyTavern 1.12.14의 일반 전송은 Generate(undefined)를 사용합니다. 이를 미지원 유형으로 거르던 문제를 수정했습니다. undefined/null/빈 문자열은 일반 생성(normal)으로 처리하고, regenerate/swipe/continue도 유지합니다. quiet·impersonate에는 RP 상태 지시를 넣지 않으며 기존 상태 주입을 제거합니다. 그 밖의 알 수 없는 유형은 주입을 추가하거나 변경하지 않습니다.

### v0.2.14 — 분석 응답 형식 오류 수정

## 주요 기능

### 장면 상태 추적

AI 응답 끝의 `<sfw_scene>{...}</sfw_scene>` 태그를 읽어 다음 상태를 기록합니다. 태그는 화면에 보이는 본문에서 제거됩니다.

- 장소
- 시간·시간대
- 환경 상태
- 중요 사물의 위치·상태
- 인물별 외형·복장, 자세·위치, 소지품, 신체 상태
- 장면 유형과 진행 단계

### 장면 유형별 진행 관리

현재 장면을 다음 유형 중 하나로 자동 분류합니다.

- 일반
- 일상
- 대화
- 로맨스
- 갈등
- 액션
- 조사·미스터리

슬로우번을 사용할 때 각 유형에 맞는 6단계 진행표가 적용됩니다. 예를 들어 액션은 위협 확인부터 결정적 행동과 후속 장면까지, 대화는 주제 형성부터 핵심 질문·응답·결정까지 별도로 관리합니다.

### 최근 전개 반복 방지

최근 AI 답변에서 이미 일어난 주요 행동·감정·서사 전개를 기록하고, 말만 바꾼 비슷한 전개가 반복되는 것을 막습니다. 문장 표현 반복을 관리하는 기존 🌀또또와는 별개입니다.

### 대사 전개 반복 방지

같은 질문·부탁·칭찬·경고·도발·사과처럼 대사의 목적이 말만 바뀌어 반복되는 것을 막습니다. 범위는 최근 1~6개의 AI 답변으로 조절할 수 있습니다.

### 대화 흐름 추적

현재 대화 주제, 답변을 기다리는 직전 질문, 이번 AI 답변에서 새로 밝혀진 사실만 기록합니다. 사용자가 이미 답했거나 주제를 바꿨다면 이전 질문을 억지로 되풀이하지 않도록 지시합니다.

일반적인 미해결 약속·목표·단서·갈등 목록은 만들지 않습니다.

### 장면 전환 연속성

설명 없이 장소가 바뀌거나 시간이 건너뛰고, 진행 중인 대화가 갑자기 끝나는 현상을 줄입니다. 본문에 이동이나 시간 경과가 자연스럽게 묘사된 경우에는 정상적인 장면 전환을 허용합니다.

### NSFW 장면 자동 인계

또또NSFW와 함께 설치하면 NSFW의 실제 담당 상태를 따라 SFW의 프롬프트 주입, 슬로우번, 태그 누락 자동 보정을 잠시 멈춥니다. SFW 단독 사용에서는 로컬 감지기를 사용합니다.

장면 신호가 2개 메시지 연속으로 사라지고 또또NSFW의 해제 브릿지까지 끝나면 또또SFW가 자동으로 복귀합니다. 건너뛴 구간 이전의 상태는 재사용하지 않고, 복귀 후 첫 AI 답변에서 현재 SFW 상태를 새로 기록합니다. 이 감지는 브라우저 내부에서 처리되므로 별도의 API 호출이 발생하지 않습니다.

### 다음 전개 힌트

AI가 제안한 다음 전개 후보 중 최근 전개·새로 확인된 사실·사용자 금지·하드 리밋과 겹치지 않는 것만 다음 생성에 힌트로 넣습니다. AI는 현재 대화 주제, 아직 답을 기다리는 질문, 새로 확인된 사실을 함께 고려해 가장 자연스러운 후보를 선택하거나 더 알맞은 전개로 이어갑니다.

### 슬로우번

선택한 강도에 따라 각 진행 단계에서 최소 1~3개의 AI 답변을 유지합니다. 같은 행동을 복사하는 것이 아니라 같은 단계 안에서 새로운 대사·반응·세부 행동을 쌓습니다.

### 태그 누락 자동 보정

상태 태그가 누락되거나 필수 항목이 비어 있으면 최근 대화를 보조 AI로 다시 분석해 상태를 복구합니다. 별도 호출 비용이 발생할 수 있으며 전용 연결 프로필을 지정할 수 있습니다.

## 기능 프리셋

- **연속성만:** 상태 추적과 갑작스러운 장면 전환만 관리
- **기본:** 연속성 + 최근 전개·대사 반복 방지
- **서사 관리:** 기본 + 대화 흐름 + 다음 전개 힌트
- **슬로우번:** 서사 관리 + 장면 유형별 단계 제한
- **사용자 설정:** 개별 기능을 직접 조합

프리셋을 고른 뒤 개별 기능을 변경하면 자동으로 사용자 설정으로 전환됩니다.

## CardInject 연동

CardInject에서 분석한 캐릭터 시트 카테고리 중 선택한 내용을 다음 전개 힌트의 참고 자료로 사용할 수 있습니다. 개입 중이며 다음 전개 힌트가 켜져 있을 때만 적용됩니다.

## 사용법

1. 확장을 설치하고 실리태번을 새로고침합니다.
2. `현재 채팅에서 사용`은 기본으로 켜져 있습니다. 필요하면 채팅별로 끌 수 있으며 마지막 선택이 저장됩니다.
3. 기능 프리셋을 선택합니다. 기본 추천은 `서사 관리`입니다.
4. 실제 다음 생성에 들어갈 내용은 장면 상태 탭의 `주입문 보기`에서 확인합니다.

또또SFW는 잔잔한 일상 장면에서도 연속성을 관리하므로 `현재 채팅에서 사용`을 켠 동안 계속 동작합니다. 또또NSFW가 함께 설치되어 있어도 그 확장의 실제 무장 상태와 최근 두 메시지의 본문 신호를 함께 확인합니다. 성적 행동이 분명하면 NSFW가 대기 중이어도 SFW는 잠시 대기합니다. 단독 설치에서도 같은 본문 차단 조건을 적용합니다.

NSFW에서 SFW로 돌아올 때는 최신 답변의 SFW 상태표를 우선 확인합니다. 누락·불완전하고 자동 보정이 켜져 있으면 최신 답변을 보조 AI로 분석합니다. 대기 중에는 최신 Info_panel에 명시된 장소·시간·날씨만 먼저 표시하며, 과거 NSFW 상태를 현재 상태로 복사하지 않습니다.

메시지 수신·생성 종료·렌더 완료·번역 등으로 인한 메시지 편집 뒤에 최신 응답을 다시 확인하며, 이벤트가 누락되어도 최신 메시지와 스와이프의 변경을 가볍게 감시합니다. 보조 분석 중 새 답변이 들어오면 오래된 결과를 폐기하고 최신 답변을 다시 분석해 시간·장소·행동·다음 장면 추천을 과거 상태로 덮어쓰지 않습니다.

보조 분석 결과를 저장할 때는 최신 응답의 `<Info_panel>`에 적힌 날짜·시간·날씨·장소를 다시 대조하며, 이 명시값이 보조 AI의 추론보다 우선합니다.

각 상태표에는 원본 메시지·현재 스와이프의 지문을 함께 저장합니다. 유저 메시지가 마지막에 있더라도 가장 가까운 최신 AI 답변을 찾으며, 과거 버그로 잘못 붙은 상태표나 내용이 다른 스와이프의 상태표는 분석 완료로 인정하지 않고 다시 갱신합니다.

- 프롬프트 주입 방식이므로 모델의 지시 이행 능력에 따라 효과가 다릅니다.
- 상태 태그를 모델이 반복해서 누락하면 보조 AI 호출이 늘어날 수 있습니다.
- 상태 항목을 많이 추적할수록 주입문 길이가 늘어납니다.
